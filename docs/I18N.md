# Internationalisation FR / EN (Kage Legacy V2)

## Couverture estimée

| Zone | Couverture | Notes |
|------|------------|--------|
| Shell UI (nav, hub, shop, BP, PvP, combat chrome, empty states) | **~98 %** | Clés `frontend/src/locales/{fr,en}.json` (parité stricte) |
| Cartes catalogue (starters + expansions) | **~100 %** | `nameFr`/`nameEn`, `descriptionFr`/`descriptionEn` via seeds |
| Talents (~150 nœuds) | **~100 %** | 3 noms volontairement identiques (Berserker, Intangible, Purification) |
| Missions combat + événements de run | **~100 %** | Migrations SQL + `missionRunService` events bilingues |
| Ennemis / boss templates | **~100 %** | `nameFr` / `nameEn` |
| Quêtes Battle Pass | **~100 %** | `description_fr` / `description_en` |
| Messages d’erreur API backend | **~40 %** | Souvent FR côté serveur ; le front affiche le message brut |
| Legacy UI (dossier `legacy/`) | N/A | Hors V2 |

**Verdict global joueur V2 : ~90–95 %** (shell + catalogue). Le principal gap restant est le **texte d’erreur API** et quelques surfaces legacy non montées.

## Mécanisme

1. **UI** — Vue I18n (`frontend/src/i18n.js`), locale initiale depuis `localStorage` (`kage-locale`).
2. **Persistance** — Profil → `PATCH /api/auth/profile/language` + `localStorage`. Landing / login ont un switcher pré-auth.
3. **Invité** — `loginAsGuest({ language })` reprend la locale UI active.
4. **Catalogue** — L’API renvoie les deux champs ; le front sélectionne via `localizedName` / `localizedDescription` (`frontend/src/utils/localeContent.js`).
5. **Narratif serveur** — `getUserLanguage(userId)` lit `sensei.language`.

## Switcher

- Connecté : menu profil (`profile-locale-fr` / `profile-locale-en`)
- Landing / auth : `LocaleSwitcher` (`locale-switch-fr` / `locale-switch-en`)
- Inscription : champ langue + sync locale

Changer de locale met à jour immédiatement les chaînes `t(...)` et les champs catalogue (computed). Les contenus déjà résolus côté serveur (chroniques liées à `sensei.language`) suivent après le `PATCH` langue.
